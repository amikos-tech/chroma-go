## Deviations from Plan

**1. [Rule 3 - Blocking] HTTPS push authentication failed; switched tag push to SSH**
- **Found during:** Task 1 Step 3
- **Issue:** `git push origin v0.3.5` over the plan's HTTPS clone URL failed with
  `remote: Invalid username or token. Password authentication is not supported for Git operations.`
  The `gh` HTTPS credential helper is not wired on this machine; `gh auth status` reports
  `Git operations protocol: ssh`.
- **Fix:** `git remote set-url origin git@github.com:amikos-tech/chroma-go-local.git`, then pushed.
- **Impact:** Transport only. Same annotated tag object, same target commit, same ref name. No
  prohibition affected (`--force`/`--tags` still not used).
- **Files modified:** none in this repo (scratchpad clone only).

**2. [Rule 3 - Blocking] Plan's constant-check grep did not match gofmt column alignment**
- **Found during:** Task 2 verify
- **Issue:** The plan verifies `grep -q 'defaultLocalLibraryVersion = "v0.3.4"'` (single space),
  but gofmt column-aligns the const block: `defaultLocalLibraryVersion                = "v0.3.4"`.
  The grep returned no match, which read as a failure.
- **Fix:** Defect in the plan's verify string, not in the code. Verified with
  `grep -nE 'defaultLocalLibraryVersion +=|localLibraryCosignMainIdentityVersion +='`, confirming
  both constants at lines 29 and 42 still read `"v0.3.4"`, and separately confirmed
  `git diff -- pkg/api/v2/client_local_library_download.go` is empty.
- **Files modified:** none.

**3. [Rule 3 - Blocking] zsh shell incompatibilities in the plan's verification snippets**
- **Found during:** Task 3 Step 2
- **Issue:** Two bash-isms failed under this environment's zsh. `${PIPESTATUS[0]}` is empty in zsh
  (it uses 1-indexed `$pipestatus`), so the first cold-cache run reported a blank exit code. A
  retry using `> "$OUT"` onto an existing `mktemp` file then failed with
  `zsh: file exists` because `noclobber` is set — that redirect failure produced a spurious exit 1.
- **Fix:** Re-ran the cold-cache check a third time without a pipe and with `>|`, capturing a
  genuine `exit 0`. **The reported exit 0 comes from that clean run, not from an inferred result.**
- **Files modified:** none.

**4. [Rule 1 - Bug] Example `go build ./...` emitted 9 binaries into the working tree**
- **Found during:** Task 3 Step 5 sweep
- **Issue:** The plan's Step 3 uses `go build ./...` inside each example dir, which writes an
  executable (`main`, or `auth`) into that dir. `git status` showed 9 new untracked binaries.
  The plan should have used `go build -o /dev/null ./...`.
- **Fix:** Removed all 9 explicitly by name with `rm -f`. **`git clean` was deliberately not
  used** (prohibited). Not added to `.gitignore` — that would be hardening beyond the locked
  "fix only" scope.
- **Files modified:** none committed.
