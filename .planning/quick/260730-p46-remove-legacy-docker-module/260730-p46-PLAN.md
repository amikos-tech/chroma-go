<objective>
Remove the legacy `github.com/docker/docker` module from the chroma-go dependency graph
(GitHub issue #522) by upgrading Testcontainers to v0.43.0, dropping the Testcontainers
Chroma module wrapper, and migrating the four test-only Docker API type imports to their
`github.com/moby/moby/api` equivalents.

Purpose: `github.com/docker/docker` is a large, `+incompatible`, frequently-CVE-flagged
module pulled in only by test files. Testcontainers v0.42+ already migrated to the split
`moby/moby/api` + `moby/moby/client` modules, so upgrading lets us drop it entirely.

Output: A dependency graph with zero `docker/docker` nodes, a Go 1.25 floor across the
root and all example modules, and all tagged test suites still compiling.
</objective>

Latest Testcontainers release is **v0.43.0** (not v0.42.0). Both
`testcontainers-go` and `testcontainers-go/modules/ollama` publish v0.43.0.

A probe module built against `testcontainers-go@v0.43.0` resolves to
`github.com/moby/moby/api v1.54.2` and `github.com/moby/moby/client v0.4.0`,
with **no `github.com/docker/docker` node at all**. This is the mechanism that
makes the removal possible.

Replacement import paths (verified present in the `moby/moby/api@v1.54.2` module cache):
- `github.com/docker/docker/api/types/container` -> `github.com/moby/moby/api/types/container`
  (`type HostConfig struct` at `types/container/hostconfig.go:418`)
- `github.com/docker/docker/api/types/mount` -> `github.com/moby/moby/api/types/mount`
  (`type Mount struct` and `TypeBind Type = "bind"` at `types/mount/mount.go`)

`github.com/docker/go-connections` is a SEPARATE module and stays. It is imported as
`github.com/docker/go-connections/nat` in `client_local_crosslang_integration_test.go`.
Do not touch it.

All Testcontainers API symbols used by this repo still exist in v0.43.0:
`GenericContainer`, `GenericContainerRequest`, `CustomizeRequest`, `WithExposedPorts`,
`WithWaitStrategy`, `Run`, and `Container.PortEndpoint(ctx, port, proto string) (string, error)`.
The upgrade is therefore purely an import-path + wrapper-inlining change, not an API rewrite.

The Testcontainers Chroma module (`modules/chroma`) is a 55-line wrapper. Its full behavior:
`Run(ctx, img, opts...)` prepends two customizers - `WithExposedPorts("8000/tcp")` and
`WithWaitStrategy(wait.ForListeningPort("8000/tcp"), wait.ForHTTP("/api/v2/heartbeat")` with a
200 status matcher) - then appends the caller's opts and calls `testcontainers.Run`.
`RESTEndpoint(ctx)` is exactly `PortEndpoint(ctx, "8000/tcp", "http")`.

Exactly ONE live call site: `pkg/api/v2/client_http_integration_test.go:850` inside
`TestClientHTTPIntegrationWithSSL`. Line 774-785 is a dead commented-out block that also
references `tcchroma`.

There are **11** example modules (the issue says 9), all at `go 1.24.11`:
array_metadata, auth, basic, custom_embedding_function, embedding_function_basic,
metadata_filters, persistent_client, reranking_function_basic, schema, search, tenant_and_db.

Every CI workflow uses `go-version-file: 'go.mod'` (14 occurrences across go.yml,
lint.yaml, nightly.yml, perf-local.yml). Bumping the go directive propagates to CI
automatically - **no workflow Go version edits are required**.

There is no root CHANGELOG.md. The only Go-version statement in docs is
`docs/go-examples/README.md:231` which reads `- Go 1.21+`.

Local toolchain is go1.26.5, so a `go 1.25.0` directive builds fine.
